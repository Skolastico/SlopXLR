# Custom Mini button layer

The embedded UI links to `/button-actions.html`. The editor configures a growable list of named pages with five actions per Mini. A 700ms cough press enters or leaves the latched action mode. In action mode two cough clicks advance a page and three go back; recognition waits 350ms after the last release, and navigation wraps. One short click does nothing in action mode. Outside it original button behavior remains, except the long cough gesture is reserved for navigation. Momentary mic mute is released when entering action mode. Navigation is disabled by default.

Bindings live in the daemon settings JSON under `button_layers`, keyed by serial number. `GET` and `POST /api/button-actions/{serial}` load and save them. These endpoints require a loopback peer, a loopback Host and a matching Origin when supplied. Saving requires a connected Mini. Profiles must exist; program actions accept existing absolute .exe paths and are launched without a shell. External actions run on a blocking worker, with their result awaited by the device actor. Shortcuts use Windows SendInput and may be blocked by integrity-level restrictions.

Button ownership is decided at press time and retained until release across mode and settings changes. A settings change does not turn an already held normal button into an action button. Reconnecting creates a fresh tracker in normal mode. Runtime state is separate from persisted bindings and is reported by the GET endpoint; POST accepts enabled and pages. Legacy actions migrate to the first page. Page count has no fixed application limit; the HTTP payload limit still applies.

Each page stores six resting colours and six pressed colours (#RRGGBB) for A–D, Bleep and Cough. Legacy pages default to purple with white press feedback. Runtime lighting overlays only these button slots, using the USB library's positions for both firmware colour formats. The underlying profile stays intact. Button states select full Colour1 while action mode is active, and profile lighting is restored on exit or shutdown. The cached overlay sends USB lighting only when the effective palette changes and is reapplied by the common colour-map path during profile loads.

The Windows notification buffer also now passes its data pointer to the driver, rather than the Vec object address, and bounds-checks notification lengths.

Validation: `cargo test -p goxlr-daemon`, `cargo clippy -p goxlr-daemon --all-targets --no-deps -- -D warnings`, `cargo fmt --all -- --check`. UI development preview: `node tests/button-actions-preview.cjs`, then `http://127.0.0.1:14565/`. The preview uses a simulated device and never contacts USB hardware or the installed Utility. Native button behavior still requires hardware validation.

The portable launcher uses a separate config and copies existing profiles on its first run. It refuses to start alongside another daemon. It does not update the installed application, enable autostart, or change drivers / firmware.

The portable package includes the installed official UI wrapper binary. Its launcher registers that local wrapper as the activator of the portable daemon and uses Activate to open or focus the native application window. The window loads the daemon's embedded interface, including the Ações dos botões link; navigation to and from the editor stays in that window.

Each binding has a Testar ação control. `POST /api/button-actions/{serial}/test` executes a single supplied action through the same device method used by physical button presses, without saving the binding or requiring action mode. The GET endpoint includes a transient last_result with success and message. Both physical presses and test requests validate only the selected action. A stale executable path in another binding no longer blocks otherwise valid actions. ToggleMute considers both muted-to-all and muted-to-X states. The selector shows the currently assigned fader channel. Media keys include the extended-key flag; shortcut execution refuses already held modifiers and releases keys in reverse order, with cleanup on partial SendInput acceptance.

Verification on 2026-10-10: nine automated tests, clippy with warnings denied, release build, JS syntax and diff whitespace checks passed. The connected Mini's Music fader C switched Unmuted → MutedToX → Unmuted using the UI test control. Invalid shortcut, missing executable and missing profile returned errors. A harmless F24 shortcut was accepted by Windows. Target application responses to multimedia keys/shortcuts, successful profile changes and physical button presses remain unverified.
